# 게임 UI 엘리먼트 메이커

> 최종 업데이트: 2026-08-17
>
> 상태: 웹 2×2·3×3·4×4 구현 및 무비용 자동 검증 완료, MCP 2×2 고정 계약 공개

## 제품 범위

- 대상: 자연어로 설명할 수 있는 독립형 게임 UI 엘리먼트
- 입력: 텍스트 필수, 선택적 스타일 레퍼런스 최대 3장
- 생성: OpenRouter의 GPT Image 2, 2K·Medium 기본값
- 웹 출력: 같은 주문의 대안 4·9·16개를 각각 2×2·3×3·4×4 정사각 시트로 생성
- 후처리: 행 우선 순서로 셀을 분리하고, 선택 시 크로마 매트를 알파로 변환
- 파생본: 원래 비율을 유지하고 긴 변 기준 32·64·128·256 PNG 보관
- 관리: 각 셀의 일반 이미지 자산과 `asset_groups` 그룹 레코드, 원본 시트, manifest, ZIP.
  휴지통·복구·영구 삭제 수명주기는 묶음 전체에 적용
- UI: 기존 422×180 형식의 전용 배너를 사용하고 이미지 배너에는 별도 저밝기 스크림을
  적용하지 않음

아이콘·버튼·프레임·배지를 고정 모드로 나누지 않습니다. 형태, 기능, 재질, 테마, 색상,
카메라, 사용 맥락을 자연어로 요청합니다. 한 시트의 모든 셀은 서로 다른 아이템 목록이
아니라 같은 요청에 대한 대안입니다.

## 사용자 흐름

1. 프롬프트 예시에서 시작하거나 원하는 엘리먼트를 직접 설명합니다.
2. 필요하면 게임 스크린샷이나 영감 이미지를 최대 3장 추가합니다.
3. 2×2(4개), 3×3(9개), 4×4(16개) 중 후보 레이아웃을 선택합니다.
4. 투명 PNG 후처리 여부를 선택하고 한 장의 시트를 생성합니다.
5. 자동 분리된 자산을 탐색해 원본·크기별 PNG 또는 전체 ZIP을 받습니다.
6. 삭제할 때는 셀 하나가 아니라 묶음 전체를 휴지통으로 이동합니다.

선택한 레이아웃은 브라우저에 보존됩니다. 요청에서 `game_ui_grid`를 생략한 기존 웹
클라이언트와 이전 작업은 계속 `2x2`를 기본값으로 사용합니다.

## 그리드와 저장 계약

지원 그리드의 규격은 `app/services/game_ui_assets.py`가 관리합니다. 프롬프트의 정확한
셀 수, 결정적 분할, 예상 자산 수와 저장 메타데이터가 같은 규격을 사용합니다. 나누어
떨어지지 않는 이미지 크기도 정수 경계로 전체 픽셀을 빠짐없이 분배합니다.

각 master PNG는 카탈로그 `kind=image`인 일반 이미지 자산으로 등록되며 metadata에는
다음 값이 들어갑니다.

- `kind=game_ui_asset`
- `game_ui_group_id`
- `game_ui_cell_index`, `game_ui_cell_count`, `game_ui_grid`
- 원본 시트와 그룹 ZIP URL
- 파생 크기 URL과 실제 크기
- 투명 처리 여부와 export 정책

그룹 manifest는 `grid`, `columns`, `rows`, `count`를 기록합니다. 기존 2×2 파일 위치와
manifest는 이동하거나 다시 쓰지 않으며, 과거 metadata를 읽는 UI도 누락값을 2×2로
해석합니다. 그룹 소유권과 조회의 기준은 SQLite 카탈로그입니다.

새 묶음은 모든 master·파생본·manifest·ZIP을 준비한 다음 자식 자산과 그룹을 하나의
SQLite 트랜잭션으로 등록합니다. 준비 또는 등록이 실패하면 그 요청에서 새로 만든 파일만
보상 정리하므로 일부 셀만 갤러리에 남는 불완전한 묶음을 만들지 않습니다.

그룹 헤더의 `묶음 삭제` 또는 갤러리 선택 모드에서 한 셀을 선택하면 전체 그룹이 하나의
선택 단위가 됩니다. 구형 클라이언트가 자식 이미지 삭제·복구 API를 직접 호출해도 서버가
그룹 전체 상태 변경으로 승격합니다. 모든 자식 sidecar와 외부 manifest를 먼저 원자적으로
기록하고, 자식·그룹 카탈로그 상태는 한 SQLite 트랜잭션으로 확정합니다. 실패하면 변경한
sidecar를 이전 바이트로 복원합니다. 관리자가 휴지통을 비우면 그룹 디렉터리와 ZIP·원본
시트·master·파생본, 자식·그룹 카탈로그 행을 함께 제거합니다. 관리자 갤러리도 묶음을
페이지 사이에서 나누지 않고 한 카드·한 삭제/복구 동작으로 표시합니다.

웹 갤러리는 묶음 보존 페이지네이션을 사용하므로 3×3·4×4 후보가 페이지 경계에서
일부만 보이지 않습니다. 이 방식은 웹이 명시적으로 요청할 때만 적용되며, 기존 API
클라이언트의 고정 크기 페이지네이션은 기본 동작 그대로 유지됩니다.

## 의도적으로 제외한 범위

- 전체 HUD 또는 완성 UI 화면
- 한 시트에 서로 다른 아이템 목록 생성
- 버튼 hover·pressed·disabled 상태 세트
- 패널, 9-slice, 엔진별 임포트 패키지
- 선택 셀의 고품질 재생성 및 유사 변형
- 가변 그리드와 그룹 관리 MCP 도구

## 현재 제약

- 모델이 정확한 셀 수와 경계를 지켜야 하며 후처리는 의미 기반 경계 검출이 아니라
  선택한 행·열 수에 따른 결정적 분할입니다.
- 같은 2K 시트를 나누므로 3×3·4×4는 2×2보다 셀당 원본 픽셀이 작습니다.
- 크로마와 가까운 전경색, 배경으로 번진 그림자·광원은 알파 가장자리에 영향을 줄 수
  있습니다.
- 웹에서는 의도적으로 개별 셀 삭제를 지원하지 않으며 묶음 전체만 삭제·복구합니다.
- 3×3·4×4의 실제 모델 준수율과 소형 가독성은 실프로젝트 표본 생성으로 확인해야 합니다.

## 검증 상태와 다음 순서

2026-08-13에 합성 2×2·3×3·4×4 시트로 다음을 자동 검증했습니다.

- 행 우선 분할 수 4·9·16과 비정수 셀 크기에서 픽셀 보존
- 투명/불투명 후처리와 32·64·128·256 파생본
- 선택 그리드의 child 수, 카탈로그 metadata, manifest, ZIP 항목 일치
- 자식과 그룹의 원자적 카탈로그 등록, 실패 시 신규 파일 보상 정리
- 그룹 단위 휴지통·복구, 구형 자식 호출의 그룹 승격, 실패 시 sidecar·DB 원복
- 영구 비우기 시 ZIP·원본·파생본·자식·그룹 카탈로그의 묶음 제거
- 웹 전용 묶음 보존 페이지네이션과 기존 고정 크기 API 응답 호환
- 기존 `split_sheet_2x2` 호출과 `game_ui_grid` 생략 시 2×2 호환
- MCP 요청 payload와 결과 계약이 계속 2×2/4개로 고정됨

같은 날 격리된 임시 DB·outputs와 가짜 provider 응답을 사용한 Edge 브라우저 E2E에서
4×4 웹 요청부터 job 완료, 결과 16셀, 셀별 4개 파생 크기와 원본 링크, ZIP 200 응답,
갤러리 16셀 자동 갱신, `size=10` 요청에서도 16셀 묶음 보존, 셀 하나 선택 시 16셀 전체가
하나의 항목으로 선택되는지, 묶음 삭제 후 0셀, 그룹 복구와 페이지 새로고침 후 16셀·레이아웃
복원, 관리자 화면의 한 그룹 카드·16셀 미리보기까지 확인했습니다. ZIP은 master 16개와
파생본 64개를 포함했고 manifest의 `grid=4x4`, `count=16`과 일치했습니다.
2026-08-17 재실행에서는 전용 Game UI 배너 적용, 스크림 투명도 0, 강제 저밝기 필터가
없는 실제 Edge 계산 스타일도 함께 확인했습니다.
이 검증은 운영 DB·outputs를 사용하지 않았고 provider 비용도 발생시키지 않았습니다.

Microsoft Edge가 설치된 Windows 호스트에서는 같은 검증을 반복 실행할 수 있습니다.

```powershell
.\venv\Scripts\python.exe -m scripts.smoke_game_ui_browser
```

기존 운영 Game UI 그룹 4개의 audit와 소유자 ZIP 200/타 소유자 404도 이전 체크포인트에서
통과했습니다. 이후 실서버에서 GPT Image 2 2K/Medium 4×4를 생성해 정상 결과를 확인했고,
2026-08-13 당시 운영 audit는 자산 1,265개·그룹 5개·누락 0이었습니다. 가장 최근인
2026-08-17 read-only 재감사는 catalog row 1,281개·active 그룹 5개·누락 0입니다. 개수는
운영 중 생성·삭제·복구에 따라 변하므로 누락 0과 정합성을 기준으로 판단합니다.
모델이나 프롬프트를 변경하면 셀 수, 경계 침범, 알파 가장자리, 후보 다양성, 32·64px
가독성을 다시 표본 검사합니다. 문제가 있으면 MCP 범위를 넓히기 전에 웹 프롬프트와
후처리를 먼저 조정합니다.

## MCP 공개 범위

`create_game_ui_assets`는 웹과 같은 dispatcher, 생성 통제, 자산 저장을 사용하지만 공개
요청 모델은 의도적으로 `grid=2x2`, 4개, 2K로 고정합니다. 입력은 prompt, 소유자 참고
이미지 최대 3장, transparent/opaque 배경, 품질 옵션입니다. MCP에는 가변 grid나 별도
그룹 목록·삭제 도구가 없습니다. 생성 결과에서 그룹 metadata와 ZIP URL을 받고
`list_image_assets`에서는 일반 image인 child 4개를 조회합니다.

같은 IP의 웹 사용자가 MCP 작업 공간을 명시적으로 연결하면 이 4개 child와 ZIP도 웹 생성
갤러리의 한 묶음으로 표시됩니다. 웹과 MCP는 같은 canonical 사내 origin을 사용해야 하며
서버 PC의 `localhost`와 사내 IP는 서로 다른 owner로 취급됩니다. 원래 MCP owner는 유지하고
웹의 `묶음 삭제`와 선택 삭제는 전체 묶음을 휴지통으로 이동합니다. 복구 API도 같은 연결을
검증해 전체 묶음을 복원하며, 연결 해제 시에는 웹 목록 관계만 제거됩니다. MCP 자체에는
그룹 삭제 도구를 공개하지 않습니다.

현재 공통 계획 계약에 따라 배경 모드와 품질이 명확하지 않으면 비용 없는
`plan_generation`이 두 결정을
반환하고 plan ID를 발급하지 않습니다. 사용자가 선택을 위임한 경우에만
transparent/medium 권장값을 적용하며, 준비된 계획과 다른 쓰기는 큐 등록 전에 거절합니다.

자동 계약과 운영 실클라이언트에서 실제 `create_game_ui_assets`, 4개 child 이미지 content,
그룹 metadata와 22개 엔트리 ZIP 다운로드를 확인했습니다. 가변 grid MCP 공개는 별도 품질
검증 후 결정합니다.
