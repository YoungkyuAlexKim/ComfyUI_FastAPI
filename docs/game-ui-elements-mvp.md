# 게임 UI 엘리먼트 메이커 MVP

> 최종 업데이트: 2026-08-13
>
> 상태: 웹 MVP 구현, MCP 2×2 고정 계약 공개

## 제품 범위

- 대상: 자연어로 설명할 수 있는 독립형 게임 UI 엘리먼트
- 입력: 텍스트 필수, 선택적 스타일 레퍼런스 최대 3장
- 생성: OpenRouter의 GPT Image 2, 2K·Medium 기본값
- 출력: 같은 주문에 대한 대안 4개를 2×2 시트로 생성
- 후처리: 4셀 분리, 선택 시 크로마 매트를 알파로 변환
- 파생본: 비율을 유지하고 긴 변 기준 32·64·128·256 PNG 보관
- 관리: 개별 자산 4개와 `asset_groups`의 그룹 레코드, 원본 시트, manifest, ZIP

아이콘·버튼·프레임·배지를 고정 모드로 나누지 않습니다. 형태, 기능, 재질, 테마,
색상, 카메라, 사용 맥락을 자연어로 요청하고 다양한 프롬프트 프리셋으로 작성법을
안내합니다. 따라서 원형 버튼처럼 여러 분류에 걸치는 결과도 별도 경우의 수 없이
표현할 수 있습니다.

## 사용자 흐름

1. 프롬프트 프리셋에서 시작하거나 원하는 엘리먼트를 직접 설명합니다.
2. 필요한 경우 게임 스크린샷이나 영감 이미지를 최대 3장 추가합니다.
3. 투명 PNG 후처리 여부를 선택합니다.
4. 후보 4개를 생성합니다.
5. 4개 자산을 그룹으로 탐색하고 개별 크기 PNG 또는 전체 ZIP을 받습니다.

참고 이미지 없이 텍스트만으로도 동일한 생성 경로를 사용합니다.

## 저장 계약

각 셀의 master PNG는 카탈로그 `kind=image`인 일반 이미지 자산으로 등록되며, 자산의
metadata에는 다음 값이 들어갑니다.

- `kind=game_ui_asset`
- `game_ui_group_id`
- 셀 순서와 전체 개수
- 원본 시트와 그룹 ZIP URL
- 파생 크기 URL과 실제 크기
- 투명 처리 여부와 export 정책

그룹은 `asset_groups`에 `kind=game_ui_group`으로 등록합니다. 기존 파일 경로와 JSON
manifest는 복구·호환용으로 유지하지만 그룹 소유권과 조회의 기준은 카탈로그입니다.

## 의도적으로 제외한 범위

- 전체 HUD 또는 완성 UI 화면
- 3×3·4×4 시트
- 한 시트에 서로 다른 아이템 목록 생성
- 버튼 hover·pressed·disabled 상태 세트
- 패널, 9-slice, 엔진별 임포트 패키지
- 선택 셀의 고품질 재생성 및 유사 변형
- 3×3·4×4 등 가변 그리드 MCP 계약

## 현재 제약

- 분리는 모델이 중앙 경계를 넘지 않는다는 전제의 2×2 고정 분할입니다.
- 크로마와 가까운 전경색은 알파 처리에 영향을 받을 수 있습니다.
- 그림자나 광원이 크로마 배경에 퍼지면 가장자리에 색 번짐이 남을 수 있습니다.
- 그룹 단위 삭제 UI는 아직 개별 이미지 삭제 수명주기를 사용합니다.

## 다음 검증 순서

1. 실제 게임 프로젝트 표본으로 셀 침범률, 알파 가장자리, 소형 가독성, 4안 다양성 측정
2. 그룹 조회·삭제 수명주기 안정화
3. 선택 셀 재생성의 제품 가치 확인
4. 품질이 검증된 뒤에만 3×3·4×4 확장 검토

## MCP 공개 범위

`create_game_ui_assets`는 웹과 같은 dispatcher, 생성 통제, 자산 저장을 사용합니다.
입력은 prompt, 소유자 참고 이미지 최대 3장, transparent/opaque 배경, 품질 옵션으로
제한하며 출력은 항상 2×2 후보 4개, 개별 관리 자산, 그룹 ZIP입니다. 가변 grid나 그룹
삭제는 공개하지 않습니다.

MCP에는 별도 그룹 목록·삭제 도구가 없습니다. 생성 완료 결과에서 그룹 메타데이터와
ZIP URL을 받고 `list_image_assets`에서는 일반 image인 child 4개를 조회합니다.

## 최근 검증 범위

2026-08-13 체크포인트에서 2×2 분할·파생 크기·그룹 저장·MCP 명령 매핑 자동 테스트와
기존 운영 그룹 4개의 audit를 통과했습니다. 기존 ZIP은 소유 principal에서 200, 다른
principal에서 404였고 manifest와 PNG를 포함했습니다. 이 체크포인트에서는 비용이 드는
신규 Game UI 실생성을 다시 실행하지 않았으므로 실제 프로젝트 표본 품질 검증은 여전히
다음 단계입니다.
